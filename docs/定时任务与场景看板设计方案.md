# 中海言析智能工作台 —「定时任务」+「场景看板」模块设计方案与实施规划

> 版本：v1.1（优化版）　|　日期：2026-08-19　|　负责人：产品（海底大大）　|　落地：web/index.html（桌面端/网页端同源）
> 结论先行：两个模块的核心改造是「**把定时任务从展示型变成可执行可观测**」+「**把场景看板从状态看板变成业务型可视化入口**」。本方案在现有 `web/index.html` 代码骨架（已含两视图、localStorage + 云端 rdb 双写、CloudBase 登录鉴权）上增量改造，不推倒重来。
>
> **v1.1 修订要点**（相对 v1.0）：
> 1. 场景看板「运行状态按业务类型」修正为：业务类型作一级分组维度，运行状态仍体现在卡片角标（不降级为内部元数据）。
> 2. 「运行/取消/下线」分两层：运行+取消=即时执行控制；下线/上线=任务生命周期控制，分置不同操作区。
> 3. 模板补「用户自配置」来源（保存为模板），三类来源齐全：系统预置 / 用户自存 / 看板库。
> 4. 发布与新建两条写入路径统一为同一场景数据模型，发布支持「更新发布」。
> 5. 排期准出去掉「单测通过」（单文件前端无测试框架），改为手动验证。
> 6. 补充取消执行的真实性说明（前端中断≠上游停止）。
> 7. 场景卡增加运行状态角标；模板「访问场景看板库」简化为直接选场景作模板。

## 1. 需求拆解总览（8 条 → 落地项）

### 定时任务模块
1. **执行能力**：新增「运行 / 取消 / 下线」三态操作（替换现有 mock「重试」）。
   - **分层澄清**：运行+取消是**即时执行控制**（点一次触发一次）；下线/上线是**任务生命周期控制**（停止/恢复调度）。两者不挤在同一操作列，分置不同 UI 区。
2. **结果查看**：新增「结果」抽屉，展示每次执行的日志、耗时、产出（对话/看板页）。
3. **状态链接**：任务状态 pill 可点击，直接跳转该任务的结果/详情视图。
4. **模板添加**：新建支持「从模板添加」，模板来源 = **系统预置 + 用户自配置 + 场景看板库**（三类齐全）。
5. **发布能力**：定时任务可「发布到场景看板」，在看板页生成对应可视化场景卡；支持「更新发布」覆盖旧版本。

### 场景看板模块
1. **业务类型维度**：运行状态改为按「业务类型」分组展示；业务类型支持「+」新增，默认仅放「存量运营」。
   - **澄清**：业务类型是一级分组维度（顶部维度条切换），**运行状态不删除**，降级为卡片角标（待运行/运行中/已完成），保留可观测性。
2. **可视化内容**：看板展示为可视化看板（图表/指标卡），数据来自「新建任务创建的页面」或「定时任务输出结果」。
3. **两行三列布局**：6 宫格 + 末位「更多+」；内容按热门应用场景排序。
4. **点击预览**：点击场景模块预览其展示页面（独立预览层）。
5. **新建场景精简**：新建页仅保留「名称 / 描述 / 业务分类 / 标签 / 开始创建」，点击后跳转新建对话对话框。

## 2. 定时任务模块设计

### 2.1 模块划分
- **任务列表层**：表格 + 状态汇总 KPI（已存在，扩展操作列）。
- **任务配置层**：新建/编辑弹窗（已存在，增加「从模板」入口 + 模板选择面板）。
- **执行引擎层（新增）**：`runTask(id)` / `cancelTask(id)`，统一调度 `agent`（`zhhs_01` 智谱 GLM 代理）真实执行。
- **生命周期层（新增）**：`offlineTask(id)` / `onlineTask(id)`，控制 `enabled` 开关，下线任务不参与调度。
- **结果观测层（新增）**：每次执行生成一条 `runRecord`，结果抽屉渲染日志 + 产出 + 跳转发布。
- **模板层（新增）**：三类模板——系统预置 `TEMPLATES` / 用户自配置（保存为模板）/ 场景看板库（直接选场景作模板）。
- **发布层（新增）**：`publishToKanban(id, opts)` 把执行结果/配置写入场景看板；支持「更新发布」覆盖已发布版本。

### 2.2 数据模型扩展
在现有定时任务对象上新增字段（不动旧字段，向后兼容）：

```js
{
  // —— 既有字段保留 ——
  id, name, freqMode, cron, cycleType, agent, prompt,
  activeFrom, activeTo, status, lastRun, duration, createdAt, updatedAt,

  // —— 新增 ——
  enabled: true,             // 上线/下线开关（下线=停止调度，生命周期层管理）
  templateId: "",            // 来源模板 id（从模板添加时填）
  sourceType: "manual|template|conversation", // 来源
  runs: [                    // 执行历史（结果查看数据源）
    { runId, startedAt, finishedAt, status:"running|success|error|canceled",
      duration, log:[{ts,msg}], output:{ type:"conversation|dashboard", refId } }
  ],
  lastRunId: "",             // 最近一次 run，状态 pill 链接指向它
  publishedTo: "",           // 已发布到的场景看板 id（空=未发布；非空=可更新发布）
  publishVersion: 0          // 发布版本号，更新发布时 +1
}
```

状态机：
- **执行状态**：`wait → running →（success|error|canceled）`（即时执行控制）。
- **生命周期**：`enabled=true`（在线）↔ `enabled=false`（已下线，调度跳过）。
- 两层正交：下线任务不可手动运行（运行按钮置灰）；上线后恢复。

### 2.3 页面结构（改造点）
保持现有「KPI 汇总条 + 表格」框架，操作列升级为**两层分离**：
- **即时执行区**（每行操作列主体）：`运行 / 取消 / 结果`。
  - 运行中按钮变「取消」；非运行中显示「运行」。
  - 「结果」打开结果抽屉；状态 pill 本身也可点击直达最近一次结果。
- **生命周期区**（每行末位或右键菜单）：`下线 / 上线`。
  - 已下线显示「上线」并整行置灰；在线显示「下线」。
  - 已下线任务「运行」按钮禁用（避免下线态误触发）。
- 新建按钮旁新增「**从模板新建**」入口 → 打开模板选择面板（见 2.5）。
- 每行「结果」抽屉内提供「**发布到看板**」（已发布显示「更新发布」+版本号）。

### 2.4 交互流程
**运行 / 取消（即时执行控制）**
1. 运行：点击「运行」→ `runTask` 置 `running` + 新增 `runRecord`（`status:running`）→ 调 `sendHome`/代理执行 prompt → 完成写入 `success`+`log`+`duration`+`output`；失败写 `error`。
2. 取消：仅运行中可点 → 前端 `AbortController` 中断 fetch，`runRecord` 置 `canceled`，任务回到 `wait`。
   - ⚠️ **真实性说明**：前端中断仅停止本地等待与 SSE 接收，**上游（智谱 GLM）不会立即停止推理计费**。首版如实标注「已取消（上游可能仍在处理）」；真正可中断的执行需上游支持 cancellation token（后续接入）。

**下线 / 上线（生命周期控制）**
3. 下线：置 `enabled=false`，整行置灰，运行按钮禁用；调度器（未来云端定时）跳过。`status` 保留原值不强制改。
4. 上线：置 `enabled=true`，恢复可运行；若原为 `wait` 则恢复待运行。

**结果查看**：点击「结果」或状态 pill → 右侧抽屉展示最近 `runRecord`：时间轴日志、耗时、产出类型（对话/看板）、「查看产出」「发布到看板/更新发布」按钮。

**状态链接跳转**：`EXEC_META` pill 包 `<a data-run="lastRunId">`，点击直达对应结果抽屉（满足需求「任务状态链接查看」）。

### 2.5 模板体系
模板三类来源（需求「我们自己配置好的」= 用户自配置）：
- **系统预置模板**：内置 `TEMPLATES`（如「每日数据巡检」「周报自动生成」「运营指标播报」），每条含 name/prompt/freqMode/默认 agent，只读。
- **用户自配置模板**：在任务编辑弹窗提供「保存为模板」按钮，把当前任务配置（name/prompt/频率/agent）存入用户模板库（持久化，跨端同步），可在「从模板新建」时选用。
- **场景看板库取模板**：从场景看板库直接选一个场景作模板（把场景的产出/prompt 作为新任务初始内容）。简化方案：不强制场景先标记 `isTemplate`，直接列出所有场景供选，选即取其上下文回填。

**添加交互**：「从模板新建」→ 模板选择面板（卡片网格，分三个 tab：系统 / 我的 / 看板库）→ 选中回填弹窗并标记 `sourceType=template` + `templateId`。

## 3. 场景看板模块设计

### 3.1 模块划分
- **业务类型维度层（新增）**：替代原状态列，维护 `BIZ_TYPES = ["存量运营", ...]`。
- **可视化内容层（新增）**：每个场景绑定一个「看板视图」（图表/指标卡），来源=新建任务产出页 或 定时任务 output。
- **布局层**：两行三列宫格 + 「更多+」末位。
- **排序层**：按 `popularity`（热门度，初始权重 + 访问计数）排序。
- **预览层**：点击卡片 → 全屏/抽屉预览该场景的可视化页。
- **新建层（精简）**：仅 5 字段 → 跳转新建对话对话框。

### 3.2 业务类型维度（替换状态维度，但保留状态角标）
- 顶部维度条：`存量运营` + 「+」按钮（点击弹出「新增业务类型」输入，写入 `BIZ_TYPES`，持久化）。
- 默认仅「存量运营」一个；用户可随时「+」扩展。
- **状态不删除，降级为卡片角标**：每张场景卡右上角显示运行状态 pill（待运行/运行中/已完成），保持可观测性；原三列状态看板布局废弃。
- 每条场景数据增加 `bizType` 字段（默认「存量运营」）+ 保留 `status` 字段；维度条切换即按 `bizType` 过滤宫格，卡片角标仍显示 `status`。

### 3.3 页面结构（两行三列 + 更多+）
```
[ 业务类型维度条：存量运营 (+) ]
┌────────┐┌────────┐┌────────┐
│ 场景卡1 ││ 场景卡2 ││ 场景卡3 │   ← 第一行
└────────┘└────────┘└────────┘
┌────────┐┌────────┐┌────────┐
│ 场景卡4 ││ 场景卡5 ││ 更多 +  │   ← 第二行末位为入口
└────────┘└────────┘└────────┘
```
- 每屏固定 6 张（2×3）；第 6 张恒为「更多+」，点击进入「全部场景」列表视图（沿用现有列表/筛选能力）。
- 卡片内容 = 该场景的**迷你可视化**（指标卡 + 趋势缩略），非纯文字。

### 3.4 看板内容来源（可视化）
两条写入路径统一为同一场景数据模型（`boardView` 字段）：
- **来源 A — 新建任务创建的页面**：对话/任务完成后若标记为「生成看板」，把产出页（图表/表格）固化为该场景的 `boardView`。
- **来源 B — 定时任务输出**：定时任务 `runRecord.output.type==="dashboard"` 时，「发布到看板」生成场景卡并带入可视化，写入 `boardView`。
- **统一模型**：两种来源都写 `boardView`（结构：`{type:"chart|table|metric", config, data, generatedAt, sourceRef}`），预览层统一渲染。
- **更新发布**：来源 B 再次发布时，若 `publishedTo` 已存在，则覆盖该场景的 `boardView` 并 `publishVersion+1`，而非新建重复卡。
- 卡片点击 → 预览层渲染完整 `boardView`（图表用现有 mermaid/图表能力或轻量 canvas）。

### 3.5 交互流程
- **预览**：点击场景卡 → 打开预览层（遮罩 + 该场景完整可视化页 + 来源标注 + 「重新生成/编辑」入口）。
- **新建场景（精简）**：点击「新建场景」→ 弹窗仅含 `名称 / 描述 / 业务分类(下拉=业务类型) / 标签 / 开始创建` → 点「开始创建」→ 关闭弹窗并唤起**新建对话对话框**（带预填场景上下文），对话产出后可回写看板。

### 3.6 排序规则（热门应用场景）
- 卡片按 `score = 基础权重(模板预设) + 0.5×访问次数 + 0.3×被发布次数` 降序；
- 同分时按 `updatedAt` 兜底；前 5 张取 Top5，第 6 张恒为「更多+」。

## 4. 数据模型与存储
- 复用现有 `localStorage`（离线缓存）+ 云端 `rdb().from('user_state')` 双写（RLS 按 `auth.uid()` 隔离，跨端互通已验证）。
- 新增持久化键：`BIZ_TYPES_KEY`（业务类型列表）、`USER_TEMPLATES_KEY`（用户自配置模板库）。
- 场景对象新增：`bizType`、`boardView`、`popularity`、`sourceRef`、`publishVersion`（关联新建任务/定时任务 id）。
- 定时任务对象新增：见 2.2。所有新增字段默认空/向后兼容，旧数据无字段时 UI 优雅降级。
- **统一写入路径**：定时任务发布、新建对话产出，都走同一个「场景写入」函数（带 upsert 语义，按 `sourceRef` 去重）。
